# Sword Deploy

## Overview

Use this workflow for this repository whenever code changes need to become Kubernetes images and be deployed. Follow the sequence strictly because `build.sh` derives image tags from the latest Git commit.

## Workflow

1. Inspect the pending changes before committing:

```bash
git status --short
git diff --stat
```

2. Commit the current project changes first:

```bash
git add .
git commit -m "<具体的这次更改信息>"
```

Use a concrete Chinese commit message that describes the actual change, for example `修复 sched switch 线程指标 key padding`.

3. Build and push images with `build.sh`.

Choose the target from the requested deployment scope:

```bash
bash build.sh sword
bash build.sh rust-mouse
bash build.sh all
```

Use `sword` for sword/sword-ebpf/sword-common changes, `rust-mouse` for rust-mouse-only changes, and `all` when both images should be refreshed.

4. Get the image tag generated by `build.sh`.

`build.sh` uses the latest commit hash truncated to 10 characters:

```bash
git log -n 1 --pretty=format:%H
```

The image tag format is:

```text
v0.1.0-<first-10-chars-of-commit-hash>
```

5. Update `deployment.yaml`.

Change only the corresponding image tags:

```yaml
xwharbor.wxchina.com/cpaas/component/sword:v0.1.0-<commit10>
xwharbor.wxchina.com/cpaas/component/rust-mouse:v0.1.0-<commit10>
```

Do not change resources, probes, node selectors, env vars, or replicas unless the user explicitly asks.

6. Apply the deployment:

```bash
kubectl apply -f deployment.yaml
```

7. Observe rollout and pod startup:

```bash
kubectl rollout status daemonset/sword-ebpf -n monitoring --timeout=180s
kubectl get pod -n monitoring -l app=sword-ebpf -o wide
kubectl get pod -n monitoring -l app=rust-mouse -o wide
kubectl top pod -n monitoring -l app=sword-ebpf --containers
kubectl logs -n monitoring -l app=sword-ebpf --tail=80 --prefix=true
```

For rust-mouse image updates, also check:

```bash
kubectl rollout status deployment/rust-mouse -n monitoring --timeout=180s
kubectl top pod -n monitoring -l app=rust-mouse --containers
```

8. Verify metrics when `sword` changed:

```bash
curl -sS --max-time 10 http://172.16.15.161:9898/metrics
curl -sS --max-time 10 http://172.16.15.165:9898/metrics
```

For thread metrics, confirm `thread_sched_switch_out_total` and `thread_offcpu_ns_total` appear on nodes where `rust-mouse` is running.

## Reporting

In the final response, include:

- The commit hash or short image tag used.
- Which images were built and pushed.
- Whether `deployment.yaml` was updated.
- Rollout status and pod restart/readiness summary.
- Any verification command that failed or timed out.
